## Findings

- **F1 (ACL2, both hosts; robustness, not soundness as far as tested)**: `repros/loop-ignore-ok/`. A book containing `(set-ignore-ok t)` and a function whose `loop$` body binds an unused variable certifies, but calling the function after `include-book` raises `Implementation error: translate11-loop$ in oneify encountered an untranslatable LOOP$ ... Please contact the ACL2 implementors`. Loading the same file with `ld` works and returns 6. Cause: `oneify` (`interface-raw.lisp`, the `loop$` case) re-translates the `loop$` when the executable counterpart is built, and at include time the book's `acl2-defaults-table` setting is not in effect, so the unused variable is a translation error. The re-translation does see the book's own earlier macros (a same-book macro in a `loop$` body works), so the only difference observed is the defaults table, which affects legality and not meaning. The parallel `lambda$` path in `oneify` has the same structure and is untested (my test book for it did not certify). Violates R3 by error. Found by `routes/run-matrix.sh` seeds 1 and 2, reduced from 80 forms by `tools/reduce.lisp`.
- **F2 (ACL2, both hosts; same root cause as F1)**: `repros/lambda-ignore-ok/`. With `(set-ignore-ok t)`, a function containing `(lambda$ (a) (let ((unused 1)) a))` is admitted and runs under `ld` (returns 7), but `certify-book` of the same file fails with `Implementation error: Translate11-lambda-object in oneify encountered an untranslatable LAMBDA$ ... even though it was supposedly translated successfully earlier`. This is the `lambda$` sibling predicted in F1; here the book cannot be certified at all. Found by the matrix's new certificate check on seed 6.
- **F3 (CCL darwinarm64 kernel, not ACL2 and not the compiler; hang, no wrong value observed)**: `repros/ccl-saved-image-write/` (`run.sh` covers plain CCL and ACL2; `NOTES.md` has the trigger matrix). In a restarted `save-application` image, an inline-compiled store into a pre-save specialised vector never returns when the store instruction and the element lie in the same 16K page. Purify copies ivectors into the read-only area next to code vectors (`lisp-kernel/arm64-gc.c`), and the W^X fault handler (`arm64-darwin-mach.c`, `arm64-exceptions.c`) flips that page RW for the write fault and RX for the fetch fault, forever. In ACL2 on CCL this is a stobj array update hanging after `save-exec` (u8, bit, u16, u32, u64, s8, s32, character fields hung; which fields are hit depends on page layout). SBCL-hosted ACL2 is unaffected. Found by the image route of the matrix (seed 9); re-run by the top-level session on 2026-11-13 at CCL `23c9edcf`. Side observation, not traced: with `:purify nil`, pre-save compiled functions crash the restarted image.
- **F4 (ACL2, host-dependent admission; not a wrong value)**: `scouts/acl2-history-new/repro-defstobj-ccl-init.lisp`. `(defstub p (x) nil)` then `(defstobj st (fld :type (or null (satisfies p)) :initially nil))` is admitted by SBCL-hosted ACL2 and rejected by CCL-hosted ACL2 with "ACL2 cannot ev the call of non-executable function P on argument list: (NIL)". Re-run by the top-level session on 2026-11-13. Root cause (`repros/defstobj-satisfies-host/README.md`): ACL2 writes the specifier into raw code as `(the (or null (satisfies p)) 'nil)` (`basis-a.lisp:8534`, `9166`) and into the accessor and updater declarations; CCL's type parser, simplifying the union of `{NIL}` with the `satisfies` type, calls the predicate on every non-numeric member constant (`ctypep`, `level-1/l1-typesys.lisp:3679`, from `type-union2` and the member intersection method), and ACL2's raw `defstub` body throws. SBCL only calls foldable built-ins there (`src/code/typep.lisp:326`). ACL2's logical check (`chk-stobj-field-type-term`) never evaluates `(p nil)`, so SBCL's outcome is the predicted one. The same rejection happens for `defun` and `let` type declarations, `the`, array element types, and for predicates that call `hard-error`, `er hard` or `time-tracker`; with a printing predicate CCL shows 32 to 66 extra calls per stobj and equal values.
- **D1 (documented logic/raw difference, not a bug)**: `scouts/acl2-stobj/probe9-maxlen.lisp`. For an `:order nil` array at its `:maximum-length`, ACL2 proves a value for `(aset1 ...)` by executable counterpart while raw `aset1` raises a hard error in `compress1`; both hosts. The release notes describe the error as intended. Not re-run by the top-level session.
- **P1 (claim, primitive sweep)**: `primitives/README.md`. 1132 ACL2 functions evaluated on every tuple from a 30-object universe (about 4.4M tuples per host), logical value vs raw value on each route: 0 value mismatches on either host. Not covered: the 31 bodiless primitives (both sides share them), 36 functions with no logical value, `string-prefixp-1` (hit its time cap), six SBCL partials. Counts are the sweep agent's; the three defects below were re-run by the top-level session on 2026-11-13, both hosts.
- **F5 (ACL2, both hosts; robustness)**: `primitives/repros/defun-ground-call-assert.lisp`. A legal recursive `defun` whose body contains the ground call `(f '(3))` is rejected with `HARD ACL2 ERROR in ASSERT$: (ASSERT$ (AND (STRINGP (CAR FN)) (ALISTP (CDR FN))) FN)`; the same shape with `(g 3)` is admitted. Agent's diagnosis (not checked by me): the null-body case of `ev-fncall-rec-logical` passes `(car arg-values)` where `fn` is meant.
- **F6 (ACL2 internal, both hosts; robustness)**: `primitives/repros/ev-fncall-rec-logical-binary-star.lisp`. `ev-fncall-rec-logical` on `binary-*` with arguments `(#\a 0)` signals a host `TYPE-ERROR` where `(0 #\a)` returns 0. The reproducer calls the evaluator from raw Lisp; whether a user-level event reaches this path is not established.
- **F7 (ACL2, both hosts; robustness)**: `primitives/repros/flush-compress-raw-error.lisp`. `(thm (equal (flush-compress x) nil))` is proved and the guard is `t`, but `(flush-compress 0)` aborts from raw Lisp with a host type error. The agent reports `throw-or-attach-call` and `null-body-er` behave the same (not re-run by me).
- **F8 (ACL2 on CCL only; soundness, `NIL` proved and a book containing it certified)**: `repros/defstobj-satisfies-host/stale-type-cache/` (`nil-via-local.lisp`, `nil-book.lisp`; `../run.sh`). Same mechanism as F4 plus CCL's specifier cache: a type simplified by calling the `satisfies` predicate is cached under the specifier text, and stays cached when the predicate later means something else. `p` is defined `local`ly as `integerp` inside an `encapsulate` where a declaration `(and (or null (integer 0 1)) (satisfies p))` is compiled, then defined at top level to accept `NIL`. `make-array :element-type` then uses the stale entry (bit vector) while the accessor's `(simple-array SPEC (*))` is parsed afresh (general vector), so a guard-verified read of a fresh `:initially 1` array returns garbage: `(g)` is `NIL`, provably `T`. No undo, trust tag or redefinition. SBCL-hosted ACL2 returns `T` and rejects the second theorem. Found by the F4 root-cause lane; independently re-run, minimized (`stale-type-cache/f8-min.lisp`, certifiable `nil-book-min.lisp`) and CONFIRMED on 2026-11-13 (CCL proves NIL and certifies the book; SBCL rejects). See `VERIFY.md`.
- **F9 (ACL2, both hosts; soundness, `NIL` proved)**: `repros/defstobj-satisfies-host/string-stobj/string-stobj.lisp`. `(defstobj s8 (a8 :type (array (or character (and integer symbol)) (2)) :initially #\a))`: `maybe-contained-in-character` (`basis-a.lisp:8548`) does not see that `(and integer symbol)` is empty, so `single-field-type-p` lets the stobj be the bare array; both hosts upgrade the element type to `character` and the live stobj is a string, which `live-stobjp` rejects. `(s8p s8)` evaluates to `NIL`, a guard-verified function returning it for a local stobj gives `NIL`, and the contradiction is proved on SBCL and CCL. Not a host divergence; found while varying array element types for F4; independently re-run, minimized (`string-stobj/f9-min.lisp`) and CONFIRMED on both hosts 2026-11-13. See `VERIFY.md`.
- **F10 (ACL2, both hosts; soundness)**: `repros/stale-compiled-file/`. `include-book` loads a book's compiled file when its write date is >= the certificate's (`load-compiled-book`, `interface-raw.lisp`) and nothing else ties the file to the book; its functions, `*1*` functions and `defconst` values then replace what the source says (constant values enter the logical world). `run.sh`: the new version is certified elsewhere, the old one is certified locally later, the new `book.lisp` and `book.cert` arrive by `cp -p`; `(include-book "book")` prints no warning, `(f 1)` is the old value, `*k*` is the old value in the world, and `nil` is proved from the book's own theorem. `race.sh`: no copying, two hosts sharing the directory, the other host recertifying within the same second (dates have 1 s resolution and each host deletes only its own compiled file). ACL2's own text concedes the mechanism (`delete-auxiliary-book-files`: "might be erroneously loaded, possibly causing inconsistency"; :DOC book-hash tells the reader to `touch` the compiled file "to avoid a warning"). Checksum book-hashes and `:load-compiled-file t` do not help; `:load-compiled-file nil` and `set-compiler-enabled nil` do. The same rule applies to `book@expansion.lsp`. Found by `routes/stale/run.sh` (11 scenarios, including a generated book).
- **F11 (ACL2, both hosts; robustness)**: `repros/portcullis-book-changed-raw-abort/`. A book certified with `(include-book "sub")` in its portcullis, after `sub` is changed and recertified: `include-book` aborts from raw Lisp with "There is a problem with the certificate, which may be described below in detail." and gives no detail; forms piped after it are discarded. The pre-alist check in `chk-raise-portcullis` (`other-events.lisp`, the `consp ch-or-cert-obj` branch) calls `include-book-raw-error` after the early compiled-file load, outside the handler that converts such errors.
- **F12 (ACL2, both hosts; soundness, documented only in a source comment)**: `repros/cross-host-reader-conditional/`. A book with `#+sbcl`/`#+ccl` certified by one host and included by the other using that certificate: the including host compiles what it reads, takes the logical body and the theorem from the certificate's cert-data, and proves `nil`. `acl2.lisp` ("Remarks on *acl2-readtable*") states that `*features*` must be the same in all phases; the certificate records neither host nor features and no check exists. With the includer's own compiled file present there is no warning at all.
- **O1 (ACL2, both hosts; documented behaviour)**: `repros/uncertified-top-stale-compiled/`. Edit and recertify a sub-book, then include the book above it without recertifying: one `[Uncertified]` warning, after which the stale compiled file and the stale certificate's translated bodies are still used; evaluation and the logical definitions disagree and `nil` is provable. :DOC uncertified-books says "all bets are off".
- **Harness note**: `routes/run-matrix.sh` inhibits `warning!`, which also inhibits `warning`, so its fasl-fallback count is always 0 and R3's control (removing the fasl) does not fire as scripted; `routes/stale/` checks the fallback with both enabled.
- **F13 (ACL2 on CCL; wrong value, no trust tag or redefinition)**: `derived-types/repros/stale-df-ftype/`. `proclaim-dfs` (`interface-raw.lisp`) proclaims `(ftype (function (double-float &optional) (values double-float &optional)) f)` for a function with a df signature. After `:u` and a new, non-df `(defun f (x) (declare (xargs :guard (rationalp x))) (+ x 1180591620717411303424))`, the table entry is removed but the proclamation is not, and on CCL a guard-verified caller `(+ (f x) (f x))` is compiled against it: `(g-gv 1)` prints `1.0E-323`, the same body with `:verify-guards nil` prints `2361183241434822606850`. With a fixnum-valued `f` the guard-verified caller faults on a memory read instead. SBCL is unaffected (its `defun` replaces the proclaimed type; both values agree). Run in fresh sessions on both hosts 2026-11-13. This is the one disagreement under T1's step for ACL2's own ftype declarations; it is not a host-compiler inference.
- **F14 (ACL2, both hosts; wrong value)**: `derived-types/repros/count-eql-vs-equal/`. `count` is defined as a macro for `count-fn` only under `#+acl2-loop-only` (`axioms.lisp`), so raw Lisp code calls `cl:count`, which compares with `eql`, while `count-listp` compares with `equal`; the guard does not restrict the item. `(count (list 1) (list (list 1)))` in a guard-verified function prints `0`, with `:verify-guards nil` prints `1`, on both hosts. Found by T1's value comparison, not by a type row.
- **F15 (CCL 1.14 runtime, not ACL2 and not type inference; wrong value and process death)**: `derived-types/repros/ccl-ash-near-fixnum-limit/`. `(ash 1 k)` for a fixnum `k` within a few bits of 2^60 returns a malformed object instead of signalling: `%ash-left` (`level-0/l0-numbers.lisp`) adds `(integer-length int)` to the count in declared-fixnum arithmetic and the sum wraps. `(integer-length (ash 1 1152921504606846975))` prints `-1152921504606846976` in plain CCL and in ACL2 (guard-verified or not; logically 2^60, and SBCL signals "can't represent result of left shift"). `(unsigned-byte-p 1152921504606846975 0)`, logically `T`, kills the process with a Mach exception. The mathematical result of the shift cannot be built, so the correct behaviour is an error. The previous worker's files in `prior-agent/` there (a book ending in a theorem `nil`) were not re-run.
- **F16 (ACL2 on SBCL; robustness, raw Lisp abort on a guard-verified function)**: `repros/df-tail-multiple-values/` (`run.sh`). `proclaim-dfs` (`interface-raw.lisp`) proclaims `(ftype (function (double-float &optional) (values t &optional)) f)` for any function with a df formal. If the body ends in a primitive whose raw definition returns two values (`floor`, `truncate`, `ceiling`, `round`), the raw function returns two values and SBCL signals `Values [2 1/2] from (FLOOR (FROM-DF X) 1) ... is not of the declared return type of the function (VALUES T &OPTIONAL)`. `(defun f (x) (declare (type double-float x)) (floor (from-df x) 1))` is admitted and guard-verified with no `skip-proofs`; `(f (to-df 5/2))` aborts, and so does `(thm (equal (f (to-df 5/2)) 2))`, discarding the forms piped after it. Binding the value in a `let` first, or a rational formal, gives 2. CCL-hosted ACL2 returns 2 and proves the theorem. Same function as F13, different defect. Found while adding df to the generator; run in fresh sessions on both hosts 2026-11-13. The generator now wraps such bodies (`*keep-f5-shape*` in `synth/base.lisp` re-enables the shape).
- **F17 (ACL2, both hosts; a legal form is rejected)**: `repros/loop-shadows-df/`. `(defun f (x) (declare (type double-float x)) (loop$ for x in (list (floor (from-df x) 1)) sum x))` is rejected with "The form X represents an ordinary object, but it is being used where a form representing a :DF was expected ... (FROM-DF X)": the target expression of a `loop$`, which is evaluated outside the loop, is translated as if the iteration variable were already bound. The same definition with the iteration variable renamed, with a rational formal, or with `let` in place of `loop$` is admitted and returns 2 (3 for `let`). Found by the generator's fresh names colliding with a df formal (seed 308); the generator now refuses that shape in `infer-loop` (`*keep-f6-shape*`).
- **F18 (SBCL 2.6.10 arm64 under ACL2; robustness, compile-time abort; root cause not traced)**: `repros/recursive-defun-inline-sbcl-arm64/` (`original.lisp` is the generated program up to the failing event, `reduced.lisp` the `tools/reduce.lisp` output after 1630 tests, `recursion-kept.lisp` the reduced body with its termination test restored). A recursive function introduced with `defun-inline`, whose recursive call takes a `loop$` with a start value computed by `df/`, aborts from raw Lisp while being admitted: `The value -262146 is not of type (SIGNED-BYTE 19)`. The same body under `defun`, the same `loop$` without `df/`, and the `df/` expression without the `loop$` are admitted; CCL-hosted ACL2 admits all three files. A 19-bit signed field is the displacement of an arm64 conditional branch, and the value is just past -2^18 in each of the three files, so the reading is that inline expansion of the recursion produces a function too large for a branch the assembler does not relax; this was not confirmed in the SBCL source, and three hand-written "clean" variants and a plain-SBCL attempt did not trigger it. Found by the fuzz loop when an IR mutation made a list-fold function inline (1 of 10,400 programs); mutation now leaves recursive functions alone (`*keep-f18-shape*`).
- **F13, second trigger (CCL)**: `repros/stale-df-ftype-stobj/`. `(defstobj st (fld :type double-float :initially 0))`, `(u)`, `(defstobj st (fld :type (unsigned-byte 129) :initially 0))`, then a guard-verified `(+ 1 (fld st))`: `Fault during read of memory address` on CCL, 1 on SBCL and 1 with `:verify-guards nil`. Found by replaying the fuzz corpus on CCL in one process (5 of 208 programs lost 29 queries that SBCL answered); `synth/batch.lisp` now gives every program that mentions df its own CCL process.
- **Generator defects the oracles caught (fixed, not findings)**: mutation changed one side of an `mbe` (real :DIFFs, twice: sites inside `mbe`, then donor variables renamed per occurrence); a mutated termination test hung REF; `let*` type declarations on a rebound name were rejected by REF; a special variable bound before its `defvar` silently disabled two protections. Each is the kind of error the REF twin and the validity counters exist to expose.

## Obligations with no entry yet

- primitives: logical body vs raw definition for every dual-defined built-in (643 raw-only regions), bounded-exhaustive over a small value universe
- control flow: hard errors unwinding through raw code; `flet` beyond the one skeleton in B1 (one local function, one formal)
- state: `defabsstobj`, fast alists, nested and local stobjs, ACL2 arrays (`aref1`/`aset1`)
- redefinition with `defun-inline` callers; `make-event` whose expansion depends on state (B1 and L4 use a quoted expansion only); `defconst` evaluated at compile vs load time
- non-numeric data: complex rationals, packages other than "ACL2" and keywords, the constrained df functions (`df-sin` ...), df values returned across function boundaries (the generator converts with `from-df` before returning)
- book fasl tampering through the `hcomp` path (a plain fasl is refused)
- the 484 unreached SBCL entries in reachable classes (`coverage/data/gap-acl2-sbcl.txt`); the loop steers by coverage but nothing yet maps a named unreached entry to the source shape that fires it. CCL: no gap classification, and the fuzz loop takes no feedback from the CCL tables
- L5 at size 3 (about 15M terms with the full operator set; needs a reduced set or sampling), and for non-integer operators
- B1 with `flet` of several functions, stobj `let*` rebinding, `loop$` with `as` and `do`; the 445 fillings excluded by the F1/F2 shape are not re-checked against a fixed ACL2
- G1 for stobj accessor guards, `loop$`/`lambda$` guards and non-integer declarations
- M1 on more seeds, and on the image route
- the context features are drawn independently; no pairwise covering array, and F16/F17/F18 show that feature interaction (df x tail position, df x shadowing, inline x recursion) is where the remaining failures are
